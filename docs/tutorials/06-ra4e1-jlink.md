# 6. On the FPB-RA4E1 board with J-Link

**English** | [Français](../tutoriels/06-ra4e1-jlink.md)

Flash the test firmware on a Renesas RA4E1 and run the tests on the board, through the on-board
J-Link probe. You get the real result of the microcontroller, the bit-for-bit comparison with the
PC, and the execution time of each function in CPU cycles.

| | |
|---|---|
| Board | FPB-RA4E1 (R7FA4E10D, Cortex-M33), on-board J-Link OB |
| Link | USB on **J9** (J-Link OB), SWD, 4 MHz by default |
| Software | SEGGER J-Link Software, Python: `pylink-square`, `pyelftools` |
| Firmware | generated by e2Unit, no e² studio project needed |

## 1. Checking the probe

Plug the board in through **J9**, then:

```
python eunit_cli.py probes
```

The command prints the serial number and name of each connected probe. Without a probe, e2Unit
stops at once with `no J-Link probe connected (USB)`.

When several probes are plugged in, choose one in `eunit.local.mk`:

```make
JLINK_OPTS := --serial 123456789
```

pylink uses the first J-Link DLL it finds. To force a version:

```make
JLINK_OPTS := --jlink-dll "C:/Program Files/SEGGER/JLink_V942/JLink_x64.dll"
```

## 2. Flashing and running

```
cd examples/emath/tests/mulq15
make test-target
```

`make test-target` chains:

1. the build of the firmware (`build/ra4e1/mulq15.elf` and `.hex`) and of the PC library;
2. the check that the `.elf` matches the specification (hash);
3. programming the `.hex` through the probe, then resetting the board;
4. for each test: reset, batches of calls through the mailbox, checks, comparison with the PC.

The output has the same form as in [tutorial 5](05-target-without-board.md), with `on jlink` and,
on each test, the measured cycle count: `(66049 samples, ... s, cycles max N)`.

To flash only: `make flash`. To run again without flashing:

```
python ../../../../eunit_cli.py run mulq15.yaml --runner jlink --elf build/ra4e1/mulq15.elf --device R7FA4E10D
```

## 3. Reading the cycles

`cycles` checks are only evaluated on the board:

```yaml
- desc: execution time
  cycles: {max: 200}
```

```
2. [PASS] execution time: cycles min ... / mean ... / max ... over 65536 calls
```

The counter is the Cortex-M33 **DWT CYCCNT**, read before and after each call:

- the cost of the measurement itself is measured at start-up and subtracted;
- the count includes the function call **and** its adapter (a few type conversions);
- `min`, `mean` and `max` cover all the calls of the test: `max` is the worst case **observed** on
  these inputs, not a guaranteed worst case.

The test firmware runs on the reset clock, without flash wait states. In the application, at a
higher frequency, flash wait states can add time: keep a margin on the limits.

The limits of the examples are deliberately loose. To set yours, run the tests once, read the
measured values in the report (`build/report/ra4e1/results.json` or the *Cycles max* column of the
Excel file), then set `max` with a margin.

## 4. What the board adds

| Check | PC | Emulator | Board |
|---|---|---|---|
| result meets the specification | yes | yes | yes |
| code built by the target compiler | no | yes | yes |
| bit-for-bit comparison with the PC | — | yes | yes |
| behaviour of the real core (FPU, bus, flash) | no | partial | yes |
| CPU cycles | no | no | yes |
| duration of `mulq15` (66,055 calls) | ~0.01 s | ~0.3 s | depends on the SWD speed |

## 5. Another board

A board is described by a `boards/<name>/` folder:

| File | Content |
|---|---|
| `board.mk` | `BOARD_CPU_FLAGS`, `BOARD_LDSCRIPT`, `BOARD_DEFS` (buffer size), `JLINK_DEVICE`, `BOARD_EMU_CPU` |
| `<name>.ld` | `FLASH` and `RAM` regions, then `INCLUDE eunit_sections.ld` |

For example [`ra4e1.ld`](../../boards/ra4e1/ra4e1.ld):

```
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x00000000, LENGTH = 512K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 128K
}

INCLUDE eunit_sections.ld
```

Then `make test-target BOARD=<name>`. Cores without DWT (Cortex-M0, M0+, M23) measure the cycles
with SysTick.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `no J-Link probe connected (USB)` | cable on the wrong connector (J9), or J-Link driver missing |
| `J-Link: ...` when connecting | e² studio debug session still open: the probe serves one program at a time |
| `e2Unit runtime not ready (no magic at 0x...)` | firmware not flashed, or another firmware on the board: `make flash` |
| `... was built from another suite version` | `.elf` older than the specification: `make target` |
| `CPU fault at PC 0x...` | the function under test crashed: `arm-none-eabi-addr2line -e build/ra4e1/<suite>.elf 0x...` |
| `p identical to host` FAIL | the target does not compute like the PC: overflow, sign extension, different `int` size, optimisation |
